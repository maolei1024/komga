# 元数据增强与个人推荐偏好

漫画继续使用 `<书库>/<作品名>/<作品名>.cbz`。手动扫描书库后，Komga 自动分析、增强元数据并同步 Gorse，不修改 CBZ。JSON、XML 可以独立存在；只有图片、信息缺失或元数据损坏都不会阻止入库。

## 分类与计数

`BOOK_ENRICHMENT_SOURCE` 每本保存一份分类来源。内容标签、作者、社团、角色和类型分别保存；译名用于显示，原始稳定键用于推荐。页数使用 Komga 分析结果，内容 Tag 数去重后计数，排除其他分类及技术分桶。内容数量未知时省略数量桶。

`METADATA` 完成字典翻译及分桶；`AI_TITLE` 独立异步执行，失败不阻塞同步。重复扫描复用未变化的来源，不重复调用 AI；人工锁定的字段优先。历史数据库升级保留已有标题和无法可靠分类的标签，不批量调用 AI。旧处理器只在一次性 Flyway 迁移中转换。

旧 XML 标签恢复使用一次性工具 `komga/tools/recover_metadata_tags.py`。优先读取归档中的 JSON，再利用同来源作品的可靠 JSON 快照；通过现有下载器认证获取的源站元数据可放入扫描快照的 `retrievedJson` 字段，须保留匹配的来源作品 URL。最后结合 XML 中保留的分类字段、历史翻译字典和当前原始标签词表恢复。无法唯一确定原始英文键但能确定为内容标签时保留原标签，不按列表位置或数量猜测对应关系。未解项继续保存在 `unclassifiedTags`。

经明确批准的回退记录带有 `fallbackTags`，`contentTagsKnown` 仍为 false。该标记只允许按当前去重后的显示 Tag 数量生成数量桶；技术桶不计入，未分类项不加入 Gorse 内容标签。预览和投递共享这一口径；系列包含任何没有可靠计数且未批准回退的书时，仍省略 Tag 数量桶。历史恢复须在备份后停写执行，不修改 CBZ，不启动 AI，不更换漫画/系列 ID 或反馈。

工具的 `scan` 子命令只读 CBZ 中的 JSON/XML 并生成临时快照，不依赖旧分析缓存中的文件清单；`plan` 结合数据库、当前字典及历史字典生成待审阅的转换计划；`apply` 仅更新分类来源和 `METADATA` 结果缓存，保留显示标签、人工锁定、标题及阅读记录。计划绑定原来源、修订号和当前标签，期间数据变化会拒绝整批提交。部署支持 `fallbackTags` 的版本并完成一致性备份后，停写执行 `apply`，启动后调用现有 `POST /api/v1/gorse/sync/items` 同步。迁移不留下长期后台任务，临时快照和计划验收后清理。

来源指纹包含分析发现的 JSON/XML 文件名。重新分析发现此前漏记的 `metadata.json` 时会重新读取分类来源；已有来源的指纹由一次性工具同步升级，避免仅因指纹格式变化重新读取整个库。旧文件清单或页数存在差异时，通过现有分析接口更新缓存，页数始终以 Komga 分析结果为准。

字典加载或人工修订时计算一次指纹，逐本处理复用内存中的字典及指纹。类型分类可以独立修订译名。作者译名用于显示，锁定译名也保留其原始推荐键；显示字段不再自动拼接命名空间前缀，人工覆盖保持原值。

Gorse 仍以系列 ID 为 ItemId，Categories 表示书库。Labels 使用 `tags`、`authors`、`groups`、`characters`、`genres`、`preference_buckets`，人工标签和作者锁定也作用于投递结果。投递时省略空分类，不发送空数组、null 或占位标签；全部为空时明确发送 `Labels: {}`。这避免当前官方 Gorse 在特征转换时因空字段丢失此前累计的特征，不影响 Komga 存储和中文显示。已有漫画需重新同步；已有人工样本和历史条目仅通过数据 API 原地清理空标签字段，保留 ID、批次及反馈，不重新应用偏好。

## 人工偏好

账户页和 Gorse 设置页提供页数与内容 Tag 数正态曲线、正负样本数量及二维分桶预览。正负合计最多 5,000 条，同桶正负冲突时不能应用。服务端按区间概率和确定性余数分配生成样本，包括开放上限桶。

作品覆盖使用与 Gorse 投递相同的规则，按用户权限和分桶定义缓存最多 15 秒；漫画或系列变更会立即失效。拖动曲线复用覆盖统计，避免反复遍历书库。

接口均以当前登录用户为作用域，位于 `/api/v1/gorse/preference-profile`：

| 方法 / 路径 | 用途 |
| --- | --- |
| GET | 读取草稿、批次状态和上一方案 |
| PUT | 保存草稿，不投递 |
| POST `/preview` | 计算分桶、冲突和有权访问的现有作品覆盖 |
| POST `/apply` | 异步应用已保存草稿 |
| GET `/status` | 查询阶段、进度及错误 |
| DELETE `/samples` | 撤回当前用户全部受管理人工样本 |

每次应用先删除该用户旧人工反馈及样本，确认清理后才插入新批次。样本 ID 为 `synthetic:komga:<用户>:<批次>:<序号>`，全部隐藏，仅带偏好桶，不混入真实内容标签。真实漫画、用户、收藏、不喜欢和阅读反馈保留。处理中重复应用返回 409；失败清理部分数据，允许重试，重启后恢复未完成任务。

投递仅调用 Gorse 数据 API。投递成功后等待 Gorse 自然更新，不清模型缓存、不重启、不强制训练。当前官方版本可能因训练样本数量不变跳过重训，因此“投递完成”不表示模型或首页已更新。

人工反馈时间排在已有真实反馈之前，批次操作时间另外记录，防止大量人工样本挤占在线召回最近反馈窗口中的真实兴趣。现役反馈 TTL 为零；如启用 TTL，需要一起重新评估该策略。

上线切换计数口径时，需要在备份后一次性删除旧人工样本及其反馈，包括无反馈的孤立样本；由用户重新设置偏好，不继承旧计数口径。推荐结果验收前保持依赖推荐执行删除的去重任务暂停。
